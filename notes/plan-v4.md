# План v4: графика и перенос на Godot 4

Решение 3 ноября: после v3.6 — графика и перенос на Godot 4. Браузерный прототип (v3.6) остаётся образцом: правила, числа и тексты берём из него, а не придумываем заново. Пока Godot-версия его не догонит, браузерная остаётся рабочей.

## Цели
- Графика уровня Stardew Valley: подробный пиксель-арт 16×16, анимации людей и зверей, свет (день и ночь, огонь, окна), погода и времена года, частицы (дым, искры, листва, снег), плавная камера.
- Текст — книжным шрифтом PT Serif в разрешении экрана (как в v3.6), пиксельный — для заголовков.
- Сборки: Windows (.exe) и веб (ссылка для проверки и показа); позже Linux и macOS.
- Механики — не хуже прототипа; одно зерно — одна игра; сохранения; автотесты и CI.

## Что проверено 3 ноября (в рабочей среде, без экрана)
- **Godot 4.7.2-stable** (последний выпуск) скачивается с GitHub releases (78 МБ, ~1 с) и работает без экрана (`--headless`).
- **Шаблоны экспорта** 4.7.2 (архив `.tpz` 1,28 ГБ; нужны только `web_nothreads_*` и `windows_*`) ставятся в `~/.local/share/godot/export_templates/4.7.2.stable/`.
- **Проба 1** (640×360, рендер Compatibility, фильтр nearest): импорт, запуск без окна, экспорт в веб (wasm ~40 МБ, без потоков — работает на любом хостинге, в том числе GitHub Pages) и в Windows (`.exe` ~109 МБ, данные внутри).
- **Проба 2** (`godot/spike/`, сборка — `sh godot/spike/build.sh`, ~9 с): режим растяжения `canvas_items` с целым масштабом — пиксель-арт чёткий (×2, ×3), а книжный шрифт (тот же урезанный PT Serif из `src/fontdata.js`, файл `.woff`) рисуется в разрешении экрана, без мыла; ночь (`CanvasModulate`), свет костра (`PointLight2D`), искры (`CPUParticles2D`) работают в веб-сборке.
- **Смотреть и тестировать:** веб-сборка открывается в Chromium без окна (WebGL 2 через SwiftShader), Playwright снимает скриншоты и читает вывод игры — как сейчас `tools/drive.mjs`. Так можно делать скриншот-тесты в CI.
- **Ограничения:** в среде нет экрана и звука — ассистент «смотрит» игру скриншотами и тестами; веб-сборка Godot не открывается из `file://` (нужен локальный сервер или GitHub Pages); `.exe` запускается двойным щелчком.

## Подход (предложение)
**А. Вертикальный срез (рекомендую):** сначала один кусок игры целиком в Godot с новой графикой — **двор столицы**: король ходит, слуги и придворные живут по распорядку, день и ночь, свет, времена года, разговор, окно совета. На нём утверждаем стиль графики, разрешение, шрифты, интерфейс; потом переносим остальное по этапам.

Другие пути:
- **Б. Сначала вся логика** (мир, экономика, ИИ) в Godot со старой графикой, потом новая графика: быстрее догоняем прототип по механикам, но долго нечего показать, а графику всё равно переделывать.
- **В. Сначала новая графика в браузерном прототипе**, потом перенос: двойная работа — браузерную отрисовку потом выбросим.

## Как переносим
- **Язык — GDScript:** встроен, работает во всех сборках, включая веб. (C# требует отдельной .NET-версии Godot.)
- **Код:** 81 модуль JS (~15,2 тыс. строк, `notes/moduli.md`) переносим по частям. Данные, таблицы и тексты — в JSON и ресурсы Godot (можно выгрузить скриптом из JS); логику — вручную, с типами.
- **Состояние:** глобальное `G` → автозагрузка `Game`; сохранения — JSON, как сейчас (совместимость со старыми сохранениями не обязательна).
- **Сверка с прототипом:** тот же генератор случайностей (порт `R`), то же зерно → тот же мир. Тест в CI сравнивает хэш карты, провинций и поселений Godot-версии с JS-версией.
- **Графика:** нынешние процедурные спрайты (портреты, звери, здания, значки) можно выгрузить из браузерной версии в PNG-атласы — как временные. Новые рисуем 16×16 в одном стиле: палитра, контур, свет сверху; чужие готовые ассеты (CC0) — только с вашего согласия.
- **Звук:** синтез WebAudio напрямую не переносится. Предлагаю записать пьесы и звуки прототипа в OGG (рендер в Chromium без окна); запасной путь — синтез в Godot через `AudioStreamGenerator`.

## Этапы
0. **Основа.** Проект `godot/` в репозитории; сборка веб и Windows одной командой; в CI — Godot и шаблоны (с кэшем), импорт, сборка, скриншот-тест; веб-сборка на GitHub Pages (по желанию).
1. **Срез «Двор».** Тайлы двора и замка с новой графикой; король и люди (ходьба в 4 стороны, анимации); распорядок дня; день и ночь, свет; времена года; разговоры; окно совета; книжный шрифт; звук.
2. **Ядро логики.** Генератор случайностей, календарь, люди и черты, генерация мира с тем же зерном (сверка хэша с JS), сохранения.
3. **Королевство.** Карта мира (тайлы, туман войны, масштаб больше нынешнего), армии и снабжение, экономика, дипломатия, ИИ держав, разведка.
4. **Битвы.** Поле, 8 родов войск, полки и приказы, ИИ, итоги.
5. **Жизнь замка и поездки.** Охота, пиры, турниры, часовня, стройки, деревни, города, чужие замки, летопись, болезни.
6. **Доводка.** Обучение и советы, меню и настройки, баланс, сборки.

Каждый этап — PR в `main`, CI зелёный.

**Где мы (ноябрь).** Этап 0 готов: `godot/slovo/` собирается одной командой (`sh godot/slovo/build.sh`), в CI (`.github/workflows/windows.yml`) — Godot и шаблоны с кэшем, самопроверка без экрана, экспорт в веб и Windows, скриншот-тест веб-сборки в Chromium; `.exe` выкладываются в выпуск `windows` на странице Releases. Этап 1 начат — срез «Двор» 0.1: заставка, двор с донжоном, казармами, конюшней, колодцем, ристалищем и садом, день и ночь (факелы — `PointLight2D`, окна — ореолы без источников света: на одну картинку в Godot действует не больше 16 огней, поэтому земля нарезана кусками 8×8 клеток), пятеро придворных с распорядком и речами, разговоры. **Срез 0.2 (5 ноября):** графика и данные берутся прямо из HTML-версии (`godot/slovo/tools/export.mjs`): все 7 мест замка, 35 человек с распорядком и речами, 20 животных, масштаб как в HTML (человек 16×32, в кадре 320×180 точек), карта света как в HTML, виды года по дням, заставка, книжный шрифт и чёткие значки. **Срез 0.3 (ноябрь): карта королевства.** Ядро этапа 2 — генератор случайностей и шум как в JS (`scripts/world/jsm.gd`) и генератор мира (`worldgen.gd`): по зерну тот же мир, что в HTML, сверка всех частей — `tools/world_check.gd` (в `build.sh` и CI). Начало этапа 3 — карта на видеокарте (`map_gpu.gd`, `shaders/map_*`): обзорная карта и куски полной детализации почти точь-в-точь как в HTML (95–99 % точек в точности), реки, дороги, мосты, леса, горы, границы провинций и держав, державы цветом, поселения и подписи, мини-карта, масштабы 1/8…2, вид года (снег, лёд, оттепель, цветение, осень, мягкая зима юга); Tab — двор ↔ карта. Мир в игре пока грузится из выгрузки HTML (генерация на GDScript ~40 с). **Срез 0.4: королевство.** Новая игра перенесена на GDScript (`scripts/sim/`: `state.js`, `dynasty.js`, `econ.js`, `intel.js` и подсказки): державы, 134 человека, 70 войск, рынки и первый день экономики, обзор и разведанные земли; состояние `G` совпадает с HTML целиком, до последнего знака (`tools/state_check.gd`, в сборке и CI). На карте — туман войны, войска и осады, подписи и державы по разведанному, подсказки и казна из симуляции, как в HTML. **Срез 0.5: время.** Часы общие для двора и карты, скорости и пауза как в HTML; день королевства (`dailyTick`: экономика по дням, жизнь поселений, войска на месте — провиант, постой, болезни, мороз, погода и распутица, смена сезонов, недельная дипломатия) перенесён на GDScript (`scripts/sim/sim_day.gd`) и совпадает с HTML день за днём весь год (84 дня, `tools/state_check.gd`); день считается кусками по кадрам (~80 мс на ПК), часы ждут, пока он не досчитан; на карте — дата, погода, распутица, кнопки скорости, лента летописи. **Срез 0.6: армии.** Войска ходят по часам — 24 шага на сутки (`scripts/sim/sim_army.gd`: цены клеток и A* как в JS — пути совпадают до клетки, походы, переправы, осады и взятия поселений, отход; бой пока «на счётах», без поля боя); замыслы держав и полководцев (`sim_ai.gd`: набор, новые войска, гарнизоны, война и мир, погони, дозоры, разбойники), вера и обман (`sim_bel.gd`: державы действуют по тому, что видели; ложный марш, костры, чучела; на карте — «призраки» чужих войск там, где их видели в последний раз), купцы с караванами, войска короны под рыцарями и дипломатия (`sim_cmd.gd`). Всё совпадает с HTML день за днём и шаг за шагом (84 дня по 24 шага, `tools/state_check.gd`). День королевства — ~210 мс счёта на ПК и ~0,3 с в браузере (пути на массивах, движение с ценами, посчитанными раз на войско); на карте войска идут плавно, видны походы, осады и взятые земли. **Срез 0.7: бои.** Настоящие бои вместо расчёта «на счётах» (`scripts/sim/sim_battle.gd`, `sim_bstep.gd`, `sim_capt.gd` — `battle.js`, `battlesim.js`, `captains.js`): поле по клетке карты, отряды, полки с воеводами, ход боя шагами по 0,1 с, ИИ полководца, итоги для войск, гарнизонов и летописи; бои ИИ тоже настоящие — и 84 дня королевства по-прежнему совпадают с HTML до знака. Ход боя на массивах шага — втрое быстрее прямого переноса (~0,7 мс на шаг на ПК, бой без экрана — около секунды, кусками по кадрам). Экран боя (`scripts/battle/`, поле на GPU): расстановка с построениями и строями, полки и отряды, приказы ПКМ и линией фронта, гонцы, стрелы, павшие, рог, натиск, бегство, итог. Король в поле (`sim_player.gd`, окна карты `scripts/world/map_ui.gd`): выезд из замка со свитой или во главе войска, путь с днями и подсказкой, погоня, встречи с врагом (бой на поле, автобой, сдача, отход), осады и штурмы, взятые поселения, войска короны — приказы с гонцами по карте, у ворот столицы — снова ко двору. **Срез 0.8: двор.** Весь день двора — на данных королевства (`scripts/sim/sim_court.gd`, `sim_birds.gd`, `sim_ext.gd`, `sim_gran.gd`, `sim_sick.gd`, `sim_tech.gd`): Малый совет и поручения советников, прошения и суд, письма и тайны, пташки Ока, династия по дням, болезни и лекари, знания королевства, амбары, королевские работы, пиры, выкупы, снабжение похода, эпохи, Совет короны и события похода; эталон HTML — с отъездом короля, 84 дня по-прежнему совпадают до последнего знака. Окна двора (`court_ui.gd`, `world/court_wins.gd`: Малый совет — K, письма — L, вести), заседание по четвергам и срочный сбор совета в замке (`court_council.gd`: король во главе стола, доклады, приказы), разговоры с советниками, казна и казармы; люди двора из королевства (семья, совет, слуги и стража, узники, облик по возрасту, постели) и приём прошений у трона (`court_audience.gd`). Звук (`scripts/snd.gd`): синтез WebAudio в Godot не переносится — `tools/snd_export.mjs` записывает его без окна в Chromium с зерном (`snd/`: 43 пьесы в OGG Vorbis, звуки, голоса мест, шумы-петли, шаги; ~19 МБ; в CI — из кэша, пока звук HTML не менялся); музыка по месту, часу и событию — как `sndui.js` и `music3.js` (семьи пьес, смена с затуханием), голоса мест и погода вокруг короля, шаги по земле места, звуки окон, королевства и боя; M — звук вкл/выкл. **Срез 0.9: замок (в работе).** Начат этап 5. Сохранения как в HTML (`scripts/sim/sim_save.gd` — `saveGame`, `loadGame`, `saveOk`): одно место, всё состояние королевства и часы, сжато (~140 КБ, ~50 мс); само раз в 7 дней, из меню, при выходе в главное меню и при закрытии окна или вкладки; после загрузки отпечаток состояния и следующий день — те же (самопроверка, веб-тест — с перезагрузкой страницы). Заставка — «Продолжить правление», новая игра (сложность, туман войны), экран загрузки; меню по Esc (сохранить, загрузить, звук, шрифт, автопауза, управление, выход в главное меню), окно звука с громкостями. Часовня, книги и темница (`court_chapel.gd` — `chapel.js`): молитва у алтаря с выборами, капеллан и милостыня, воскресная обедня (колокол, люди на скамьях, проповедь, верность домов), чтение — навыки короля, узники (допрос, выкуп письмом, служба, помилование, казнь) и тюремщик. Пир (`court_feast.gd` — `feast.js`): в день пира с 17:00 зал полон — семья и совет за высоким столом, знать домов и придворные за столами, менестрель с нотами, блюда; во главе стола — до трёх дел (кубок за знать, почести дому, песнь о деяниях, застольные сплетни, танец или состязание), разговоры с гостями; предметы мест по условию (`when`: пир, готовая стройка). Стол зодчего (`court_works.gd` — `projects.js`): окно «Замыслы и стройки» (12 замыслов, цена и дни, заложить, свернуть), леса на месте постройки растут по ходу работ (картинка сверена с HTML попиксельно), место занято, двое мастеров с распорядком и «на пиво», готовые постройки на своих местах, звездочётная — труба ночью. Турнир (`court_tour.gd` — турнир из `feast.js`): с трибунами у ристалища в день турнира с 10:00 до 16:00 — семья и совет на трибунах, зрители от домов, герольд, восемь рыцарей, поединки на виду (кони под попонами в цветах домов, копья в щепки, выбитый из седла), панель турнира; король выходит к барьеру сам (E, когда копьё на середине щита), награда победителю, итог — в летопись. Раны (`court_hurt.gd` — `hurt.js`): ушиб, рана, тяжёлая рана, значок и медленная ходьба; лечение — носилки к донжону, лекарь и супруг(а) у постели, дни в постели, жар. Простые дела двора и сон (`court_acts.gd` — `doAct`, `bedDialog`, `sleepUntil`): постель — спать до утра или отдохнуть пару часов (тьма, часы бегут, королевство догоняет, весть будит), вид двора по казне и амбару (кучки золота, мешки, колыбель, игрушки), колыбель, амбар, лавка купца, чучело (шаг к Мечу короля), фонтан, кухня, колодец, кузня; на паузе двор замирает, как в HTML. Больные при дворе (`court_sick.gd` — `sick2.js`): лекарь двора — человек с распорядком и обходом лежачих, больные в своих постелях с подписью «болен: …», у постели — пожелать выздоровления, прислать лекаря (лечение, терияк, отделить заразного), завеса у отделённого; разговор с лекарем (доклад, осмотр и отвар, лекари и жалованье, поход, ворота от мора); король занемог — лекарь велит лечь (сцена лечения с днями болезни) или «перемогусь на ногах», значок болезни. Дальше в 0.9 — охота; потом 1.0 — поездки (деревни и чужие замки). Рядом — та же браузерная игра для Windows в окне Electron (`desktop/`). Открытые вопросы 2–4 по умолчанию решены так: оба способа (Windows `.exe` и браузер), тёплый стиль ближе к Stardew, 640×360 с увеличением ×2/×3.

## Открытые вопросы
1. Подход: срез «Двор» (рекомендую), сначала логика или сначала графика в браузере?
2. На чём играть: Windows `.exe`, браузер (ссылка GitHub Pages) или оба?
3. Стиль: ближе к Stardew (тёплый, сочный) или темнее, «средневековая миниатюра»? Можно ли брать готовые CC0-ассеты?
4. Размер пикселя: 640×360 (как сейчас, ×2 / ×3) или 480×270 (крупнее, как в Stardew)?

## Как повторить проверку

```bash
mkdir -p /data/tools/godot && cd /data/tools/godot
R=https://github.com/godotengine/godot/releases/download/4.7.2-stable
curl -sSLo godot.zip $R/Godot_v4.7.2-stable_linux.x86_64.zip && unzip -oq godot.zip && chmod +x Godot_v4.7.2-stable_linux.x86_64
./Godot_v4.7.2-stable_linux.x86_64 --headless --version          # 4.7.2.stable.official.ed1daf0bf
curl -sSLo templates.tpz $R/Godot_v4.7.2-stable_export_templates.tpz
T=~/.local/share/godot/export_templates/4.7.2.stable && mkdir -p $T
unzip -oqj templates.tpz templates/version.txt templates/web_nothreads_release.zip templates/web_nothreads_debug.zip \
  templates/windows_release_x86_64.exe templates/windows_debug_x86_64.exe templates/linux_release.x86_64 -d $T && rm templates.tpz
cd /data/game && sh godot/spike/build.sh                          # → godot/spike/build/web, build/win
cd godot/spike/build/web && python3 -m http.server 8765           # открыть http://localhost:8765/
```

Скриншот в Chromium без окна: Playwright с флагами `--use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist`; ждать в консоли строку `ready:` от игры.
